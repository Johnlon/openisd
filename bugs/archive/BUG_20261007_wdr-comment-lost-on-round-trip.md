# The .wdr Comment is not the driver's source URL

**Status:** RESOLVED 2026-10-07

## Symptom
A `.wdr` written from a record with no comment of its own had an empty `Comment=`, or the stored
note "Generated by OpenIsd". John's ruling: `Comment=` holds the driver's source URL.

## Evidence
- winisd_tools bugs BUG_20260822 (comment content diverges: URL vs model name) and BUG_20260824
  (round trip always loses the original Comment).
- 975 stored `winisd.wdr` files in winisd_drivers carry "Generated by OpenIsd"; none carry a URL.

## Cause
`openIsdDriverToWinIsdDriver` wrote `driver.comment.value ?? ""`. Import already kept an incoming
Comment (the round trip was fine); a record with no comment had no URL fallback.

## Fix
`wdrCommentOf` in `packages/design/domain/winIsdDriverConverter.ts`, the one place the Comment is
built: own comment unchanged; else manufacturer datasheet URL, else product page, else listing
page; else empty. The `[DQ]` lines still follow after the line break.

## Verification
`packages/design/test/winisd/wdr-comment.test.ts`: incoming kept (with line break), URL, datasheet
over other URLs, URL + `[DQ]` suffix, empty.

## Not done here
The stored `winisd.wdr` files in winisd_drivers need regenerating by winisd_tools. The scrapers'
`driver.yml` `comment: Generated by OpenIsd` also still travels through as the record's own comment.
