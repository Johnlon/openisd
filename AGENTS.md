## Duplicate-logic check on every pull request

`scripts/dupscan.mjs` runs in the `architecture` job of `.github/workflows/pr.yml` (pull request and merge queue). It finds copies of code with jscpd (pinned devDependency) and lines that match the formula rules (driver-count scaling, resonance, dB, air, unit factors, maths in `packages/ui`), and exits 1 on any finding not listed in `scripts/dupscan-allow.json`. A new copy of a formula therefore fails the pull request until the copy is removed (call the engine instead) or John allows it. Findings that existed on 18 Nov 2026 are the baseline, each with reason "baseline 2026-11-18 (QO946.c256)" (John, 18 Nov 2026, "yes" to making the scan a check on every pull request). Test: `bash scripts/test/dupscan.test.sh`.

`scripts/dupscan-allow.json` is a gate file (listed in `GATE_FILES` in `land.conf`, John 18 Nov 2026, board item QO948: a pull request that changes it is refused unless its task has `gates_approved: QO<n>` for a board item John answered): a key added to it needs a `reason` that quotes a John ruling. Agents never add keys on their own and never regenerate it with `--write-baseline` (standing rule "No agent weakens anything on its own"). A key is never removed. When a copy is consolidated into the engine, its entry stays and is marked resolved: `"resolved": true, "resolved_to": "<engine file>:<function>", "resolved_by": "<task id>", "ruling": "QO949"` (John, QO949, 18 Nov 2026: "old entries stay, marked 'resolved, resolved to <engine function> by T902'; a resolved copy that reappears fails; T902 and future consolidations recorded so"). A resolved key never allows its copy: if it reappears the check fails and names the function to call. An allowed entry whose copy is gone fails the check until it is marked resolved (T911).
