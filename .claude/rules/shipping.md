# Shipping — what `ship.sh` checks, and what only you can

John, 15 Nov 2026 (QO923): decided ways of working are written down and enforced. The lead's side of the same lessons:
`_agent_files/LEAD_PLAYBOOK.md` §2–§3 (workspace root). Each line: the mistake, then what stops it.

1. **A `done_test` names a unit spec, never a browser spec.** Refused by `ship.sh` (task contract, before the push) and by `pr-gate`'s `done-test`.
2. **Run every architecture test and `branch-map.test.ts` before shipping.** `ship.sh` runs `scripts/land/unit-architecture.sh` (every architecture test plus `packages/ui/test/scripts/branch-map.test.ts`: every UI branch is mapped to a view) and refuses on red. `--no-local-check` skips it; the same list fails `pr-gate` after the push.
3. **A change to a record or index-row shape reaches tests in other packages.** `unit-changed.sh` runs the tests the import graph reaches and, since type imports are erased, every test that names a type whose declaration you edited (`scripts/lib/typeReach.mjs`). Still run the other packages' tests that build such rows by hand (persistence, `ui/test/logic`): `grep -l '<TypeName>' packages/*/test`.
4. **A PR is shipped when it is queued, not when `ship.sh` returns.** `ship.sh` asks GitHub and exits 1 ("NOT queued") when no auto-merge request exists. GitHub drops the request when the PR is ejected from the merge queue (a PR ahead of it failed): run `bash scripts/land/pr-queue.sh <n>`; it says merged, auto-merge or in-merge-queue, or re-queues and confirms.
5. **Label and retitle with the REST call, never `gh pr edit` (any form fails here: Projects classic; `ship.sh` re-shipping an open PR failed on it until T815)**. `bash scripts/ship.sh T<n> --fixes`, or `label: fixes` in the task file, labels for you. By hand: `gh api -X POST repos/portingle/openisd/issues/<n>/labels -f 'labels[]=fixes'`.
6. **`pr-gate` runs no browser specs.** A change to a consistency check, a rule, a shared layout or a limit can break a browser spec that exercises it, and only the post-merge suite shows it (the Vas allowance; a phone layout at 412x600). No gate does this for you: browser specs drive the app through the screen, so no import graph links them to the source, and 237 specs do not fit the gate's 5 minutes. Before shipping, find the specs that mention what you changed (`grep -l '<rule id, message text or field name>' packages/*/test/**/*.browser.spec.ts`) and run them with `bash scripts/test.sh <spec…>`. Say in the task's release note or the PR which you ran.
7. **`ship.sh` removes the worktree at once** (a red PR is fixed in a fresh worktree from its branch). To fix a red check: `bash scripts/land/pr-fix.sh T<n>` prints the new worktree; edit there, `bash scripts/ship.sh T<n>` again (it reuses the PR and re-confirms the queue). `ship.sh` prints this command on success.
8. **Count suite failures by Playwright outcome `unexpected`, never by result status.** `test.fail` cases report status `failed` and are expected. `scripts/lib/testOutcome.mjs` does this for `extract-failing-tests.mjs`, `analyze-telemetry.mjs` and `rerun-failing-tests.mjs`; any new summary tool uses it.
9. **A parser of someone else's file format is tested against a real sample of that format, never a hand-written one** (T815's first report parser read a `outcome` key Playwright's JSON reporter never writes; its hand-made fixtures agreed with the bug). Cut a small fixture from a real file (`packages/ui/test/scripts/fixtures/pw-report-sample.json` is the model) and say in a comment where it came from.
10. **A held pull request stays held.** A lead or reviewer holds a PR with the label `hold`. `pr-gate`'s `hold` job (`scripts/ci/check-hold.sh`) is red while it is on, on the PR and in the merge queue, so no push or `gh pr merge --auto` can merge it; `ship.sh` and `pr-queue.sh` push but never queue it and say HELD. Never remove the label, never queue the PR yourself: the holder lifts it. The gate re-runs when the label changes.
