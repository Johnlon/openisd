### Concrete Unresolved / New Defects

1. **New edge case: `Shift+Tab` into `<input>` when `underlineIndex === null` (e.g. right after switching units on `unitEl`) selects the whole input and marks index `0` ([`NumInput-hooks.ts:L89-L107`](http://lap:8000/winisd/openisd-t607/packages/ui/src/hooks/NumInput-hooks.ts#L89-L107), [`NumInput-hooks.ts:L365-L375`](http://lap:8000/winisd/openisd-t607/packages/ui/src/hooks/NumInput-hooks.ts#L365-L375))**
   - **Mechanism**: Toggling the unit while `unitEl` is focused sets `underlineIndex.value = null` and collapses the selection to `display.value.length` ([`NumInput-hooks.ts:L89-L94`](http://lap:8000/winisd/openisd-t607/packages/ui/src/hooks/NumInput-hooks.ts#L89-L94)). If the user then presses `Shift+Tab` from `unitEl` back to `inputEl` (or enters the group backwards via `Shift+Tab` through `▼` → `▲` → `unit` → `input` without spinning), `onFocus` takes `if (!entering)` (`groupFocused.value` is already `true`) and skips the `nextTick` fixup because `digit === null` ([`NumInput-hooks.ts:L105`](http://lap:8000/winisd/openisd-t607/packages/ui/src/hooks/NumInput-hooks.ts#L105)).
   - **Consequence**: The browser's default keyboard focus selects the entire text `[0, display.value.length]` (hidden by `input[data-numinput]::selection { background: transparent }` in [`field-catalogue.css:L84`](http://lap:8000/winisd/openisd-t607/packages/ui/src/ui/field-catalogue.css#L84)), and `selectionchange` → `rememberCaret()` sees `selectionStart = 0, selectionEnd = length`, setting `lastCaret = {kind: 'caret', at: 0}` and `underlineIndex.value = 0` (highlighting the leading digit while the full value is selected).
