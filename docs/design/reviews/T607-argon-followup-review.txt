#### 2. [`num-input-rendition.browser.spec.ts`](http://lap:8000/winisd/openisd-t607/packages/ui/test/ui/num-input-rendition.browser.spec.ts#L105-L136)
- **Case 1 (`a refused draft retains its text but loses the digit marker when focus leaves`, lines 105–118)**: Directly verifies the refused-draft blur path (`refusal.value !== ''`). Entering `'0'` on a positive-floor specimen, placing the marker with `ArrowLeft`/`End`, and clicking the page heading proves `.num-mark-underline` drops to count `0` while value `'0'` and the refusal `title` remain.
- **Case 2 (`leaving the field stops held keyboard spinning before key release`, lines 121–136)**:
  - **Why selecting the ones digit (`setSelectionRange(1, 2)`) works**: On valid blur, `fmt(props.modelValue)` reformats `'11.0000'` to `'11.000'` (3 decimal places), resetting DOM selection and dropping index `6` out of bounds (`lastCaret = {kind: 'digit', at: 6}`). Selecting index `1` keeps `lastCaret` (`{kind: 'digit', at: 1}`) valid in `'11.000'`, so an unstopped repeat timer continues stepping `11.000 → 14.000` over `1000ms`.
  - **Low-severity test gap (Verified)**: Case 2 tests `stopRepeat()` on a **valid** draft (`11.0000`, where `refusal.value === ''`), which already reached `stopRepeat()` prior to this patch. To exercise the newly fixed **refused-draft** `stopRepeat()` path (`refusal.value !== ''` at line 549), a test would need to blur while holding `ArrowDown` after stepping down into a refused floor state (e.g., `1.000 → 0.000` on a positive-floor field where `min = 0` but `0` is refused).
