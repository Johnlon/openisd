**Reviewer:** Gemini Argon High (First, Strategy-Only Review)  
**Scope Notice:** **This first review is a strategy and architecture critique only. It is NOT code signoff, test signoff, or visual signoff.**

## 1. Executive Verdict on the Strategy

The written strategy in [FIELD_APPEARANCE_CATALOGUE.md](http://lap:8000/winisd/openisd-t607/docs/design/FIELD_APPEARANCE_CATALOGUE.md?html#L147-L284) and the interaction contract in [field-use-cases.html](http://lap:8000/winisd/openisd-t607/docs/design/field-use-cases.html#L15-L170) identify the right target architecture (one shared `Field` + `FieldAppearance` + `UIFieldBody` pipeline, zero ad-hoc shell inputs, and deterministic visual/behavioural contracts), **but the strategy as written is flawed in five critical ways**:

1. **It treats the current CSS and component layer as a near-complete implementation needing only shell layout tweaks**, when in reality [field-catalogue.css](http://lap:8000/winisd/openisd-t607/packages/ui/src/ui/field-catalogue.css#L1-L109) is a `:is(...) !important` override stylesheet bolted onto legacy markup that actively breaks provenance colours, inverse-video cursor rendering, keyboard focus order, and desktop pane widths.
2. **It misdiagnoses why the desktop shell fails layout gates**, blaming container sizes when the actual culprits are (a) forcing a fixed 5-column `348px` minimum width (`minmax(70px,1fr) 108px 48px 80px 22px`) onto *every* `.ui-field` even when unitless, read-only, or without `≠W`, and (b) widening `.left-sidebar` from `175px` to `300px`, which stole `125px` from `.content-panel`.
3. **Its proposed test oracle is currently circular and selector-blind**: [field-renditions.browser.spec.ts](http://lap:8000/winisd/openisd-t607/packages/ui/test/ui/field-renditions.browser.spec.ts#L30-L62) compares synthetic `?field-catalogue=1` fixtures only against `#case-03` (`entered`), and [compactFieldContract.ts](http://lap:8000/winisd/openisd-t607/packages/ui/test/fixtures/compactFieldContract.ts#L16) only inspects `.ui-field[data-field], .mob-sheet-cell[data-field]`, completely ignoring dozens of unmigrated raw controls in [OriginalShell.vue](http://lap:8000/winisd/openisd-t607/packages/ui/src/ui/shells/original/OriginalShell.vue) and [UIPickField.vue](http://lap:8000/winisd/openisd-t607/packages/ui/src/ui/components/UIPickField.vue).
4. **It conflates two divergent implementations of the interaction contract**: the gallery inline script in [field-use-cases.html](http://lap:8000/winisd/openisd-t607/docs/design/field-use-cases.html#L194-L322) and the production hook in [NumInput-hooks.ts](http://lap:8000/winisd/openisd-t607/packages/ui/src/hooks/NumInput-hooks.ts#L1-L598) do not share DOM structure, cursor rendering, or state transitions.
5. **It sequences full-app rollout ahead of John's approval of the remaining 22 gallery cases**, risking mass rework while leaving known gallery defects (missing `≠W` popups on Cases 09–16, Case 19 checkbox centering) unfixed on the approval page itself.

## 4. Missing Dimensions, Circular Oracles, Architectural Mistakes, Sequencing Risks & Untestable Promises

### 4.1. Architectural Mistakes Causing the Current Desktop Shell Failures
The strategy notes two open failures in [original-shell-layout.browser.spec.ts](http://lap:8000/winisd/openisd-t607/packages/ui/test/ui/original-shell-layout.browser.spec.ts) (`vented` horizontal overflow `1112px > 1057px` and `pr` vertical pane height `247px > 226px`), and proposes tweaking shell containers. **Inspecting the CSS reveals the root causes are architectural mistakes in the rendition layer itself:**
1. **Every `.ui-field` is forced to reserve 5 fixed columns (`348px` minimum width):**  
   [field-catalogue.css:L2-L7](http://lap:8000/winisd/openisd-t607/packages/ui/src/ui/field-catalogue.css#L2-L7) applies `grid-template-columns: minmax(70px,1fr) 108px 48px 80px 22px !important` to **every** `.ui-field`. A read-only field with no spinners still reserves `80px` of empty space in column 4; a unitless field still reserves `48px` (or `156px + 80px + 22px`); a field whose `FieldAppearance.canShowWinisdDiff` is `false` still reserves `22px` in column 5.
2. **Widening `.left-sidebar` from `175px` to `300px` ([T607-progress.md:L343](http://lap:8000/winisd/openisd-t607/tasks/T607-progress.md?html#L343)) stole `125px` from `.content-panel`:**  
   In the `1600×400` short-window test ([original-shell-layout.browser.spec.ts:L298-L323](http://lap:8000/winisd/openisd-t607/packages/ui/test/ui/original-shell-layout.browser.spec.ts#L298-L323)), Vented Enclosure needs `~1112px` across its 3 columns (`vent-config-col` + `vent-dims-col` + 4-field column), which previously fit inside `1600 - 175 - 200 = 1225px` but now overflows `1600 - 300 - 200 = 1100px` (`clientWidth = 1057px`) by `55px`! Widening the entire left sidebar on all tabs just to fit `.ui-field` inside the collapsible Signal Generator drawer is an architectural mistake.
3. **Multi-port (`bandpass6`, `abc`) 6-field-across layouts are ignored by the strategy:**  
   In [OriginalShell.vue:L624-L666,L1352-L1367](http://lap:8000/winisd/openisd-t607/packages/ui/src/ui/shells/original/OriginalShell.vue#L624-L666), `.vent-pane-tight` places 3 port columns side by side, each with a 2-column `.vent-Subgrid` (6 fields across) using stacked labels (`grid-template-rows: auto auto`) and `70px` inputs. Under `.compact-fields` (`!important` single-row `348px` fields), 6 fields across requires `> 2000px`! The strategy does not explain how 3-port (`bandpass6`/`abc`) panes are laid out without stacked labels or horizontal scrollbars.
4. **PR pane height (`247px` vs `226px`, hard ceiling `< 240px` in [original-shell-layout.browser.spec.ts:L240](http://lap:8000/winisd/openisd-t607/packages/ui/test/ui/original-shell-layout.browser.spec.ts#L240)):**  
   Every other tab has at most 5 rows (`5 × 40px + 26px = 226px`). The PR tab ([OriginalShell.vue:L575-L618](http://lap:8000/winisd/openisd-t607/packages/ui/src/ui/shells/original/OriginalShell.vue#L575-L618)) stacks a full-width PR picker row (`34px` + `8px` margin) + `.sub-section-header` (`23px`) + four `40px` rows (`160px`) + `20px` panel padding = `245–247px`.

### 4.4. Untestable Promises
- The strategy promises **"`0px` tolerance" across Chromium, Firefox, and WebKit** ([FIELD_APPEARANCE_CATALOGUE.md:L193-L202](http://lap:8000/winisd/openisd-t607/docs/design/FIELD_APPEARANCE_CATALOGUE.md?html#L193-L202)) for all geometry and typography. While CSS box dimensions (`width`, `height`, `padding`, `border`) can be asserted to `≤ 0.5px` (`Math.round`), **subpixel glyph widths (`scrollWidth`), native `<select>` arrow chrome, and `<input type="date">` internal layout vary across Chromium, Firefox, and WebKit engines**. Comparing an app control against the gallery reference mounted in the *same* browser engine at runtime is valid (`0px` box delta within the same browser), but hardcoding Chromium pixel constants for text glyph widths across Firefox/WebKit will flake unless compared dynamically against the same-engine reference element.

## 5. What Must Change Before Implementation Continues

1. **Fix the gallery approval page (`docs/design/field-use-cases.html`) first** so Cases 09–16 have working `≠W` popups, Case 19 checkbox is vertically centered, and unit switching updates/re-validates caret state as promised by its own contract.
2. **Unify the cursor/digit rendering architecture (`NumInput.vue` + `field-catalogue.css`)** with `field-use-cases.html`: make the `<input>` text transparent when `.num-mark-overlay` is active (or always), align overlay padding/border box identically (`1px` border + `6px` padding), and use `currentColor` / CSS custom properties (`--field-fg`) in `@keyframes spin-inverse-blink` instead of hardcoded `#078200` so calculated (`#06f`) and defaulted (`#23548f`) fields keep their provenance colour when focused.
3. **Eliminate the read-only = calculated conflation**:
