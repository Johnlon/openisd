### 2. Concrete Defects & Source Criticisms

1. **Wrong screen captured in `prod-phone-stable.png`**:
   - [prod-phone-stable.png](http://lap:8000/winisd/openisd-t607/build/ui-contract/driver-info-v1/prod-phone-stable.png) was captured on the **Box** tab (`Vented`, `Vb`, `Fb` with the sync banner), not the **Driver** tab. It provides no production baseline for the mobile Driver tab.

2. **`projectInfoOpen` state leak if `browseOpen` closes outside `closeLibrary()`**:
   - [`DriverBrowser.vue:L39`](http://lap:8000/winisd/openisd-t607/packages/ui/src/ui/components/DriverBrowser.vue#L39) watches `presentationState.browseOpen` and calls `pickDriver(null)` when it turns `false`, leaving `projectInfoOpen.value = true` if anything closes the overlay by mutating `presentationState.browseOpen = false` rather than calling [`closeLibrary()`](http://lap:8000/winisd/openisd-t607/packages/ui/src/logic/driverBrowsingState.ts#L565-L570).
   - If `projectInfoOpen` remains `true`, the next `Select driver` open mounts `DriverLibrary` in `DriverListMode.Info` and [`openedLibrary()`](http://lap:8000/winisd/openisd-t607/packages/ui/src/logic/driverBrowsingState.ts#L574) returns early without calling `init()` or `reloadMyDrivers()`, stranding the picker on `"Loading…"`.
   - **Fix**: Watch `presentationState.browseOpen` inside [`driverBrowsingState.ts`](http://lap:8000/winisd/openisd-t607/packages/ui/src/logic/driverBrowsingState.ts#L565-L570) (not `DriverBrowser.vue`) so `!browseOpen` always resets both `projectInfoOpen.value = false` and `previewDriver.value = null`.

3. **False-positive post-Close picker check in browser and unit tests**:
   - After closing `Info` and clicking `Select driver`, [`driver-info.browser.spec.ts:L34-L36`](http://lap:8000/winisd/openisd-t607/packages/ui/test/ui/driver-info.browser.spec.ts#L34-L36) only checks `await expect(page.locator('.wb-modal .preview')).toHaveCount(0)`. An uninitialized library stuck on `"Loading…"` also has `.preview` count `0`. The spec should assert that catalogue rows (`.ditem`) or `initialized` actually load after closing `Info`.
   - Similarly, [`driverBrowsingState-info.test.ts:L26-L32`](http://lap:8000/winisd/openisd-t607/packages/ui/test/logic/driverBrowsingState-info.test.ts#L26-L32) asserts `initialized.value === false` during `Info` and then calls `closeLibrary()`, but never calls `openedLibrary()` a second time after `closeLibrary()` to prove normal picker initialization resumes.

4. **Weak geometry assertions in [`driver-info.browser.spec.ts:L19-L20`](http://lap:8000/winisd/openisd-t607/packages/ui/test/ui/driver-info.browser.spec.ts#L19-L20)**:
   - `expect(boxes.every(box => box.left >= 0 && box.right <= host.width)).toBe(true)` only verifies horizontal viewport bounds. It does not assert that the three buttons stay on a single row (`boxes[0].top === boxes[1].top === boxes[2].top`), do not overlap (`boxes[0].right <= boxes[1].left`), maintain equal height, or that phone `Info` is `44px × 44px`.

5. **Empty `.browser-footer` rendered below `.preview` in [`DriverLibrary.vue:L371-L377`](http://lap:8000/winisd/openisd-t607/packages/ui/src/ui/components/DriverLibrary.vue#L371-L377)**:
   - `v-if="!previewDriver"` is on the inner `<div>` instead of `<div class="browser-footer">`. When `previewDriver` is shown (including `Info`), `.browser-footer` remains in the flex column with `padding: 4px 0 2px` plus `.driver-library`'s `gap: 6px`, adding 12px of empty bottom padding under the `.preview` box in [info-desktop-final.png](http://lap:8000/winisd/openisd-t607/build/ui-contract/driver-info-v1/info-desktop-final.png) and 6px in [info-phone-final.png](http://lap:8000/winisd/openisd-t607/build/ui-contract/driver-info-v1/info-phone-final.png).

6. **Per-render object allocation for phone `Close` CSS variables ([`DriverLibrary.vue:L360`](http://lap:8000/winisd/openisd-t607/packages/ui/src/ui/components/DriverLibrary.vue#L360))**:
   - `:style="Object.fromEntries(PhoneRowSizes.CLASSIC.cssVars())"` rebuilds the style object on every render because `DriverBrowser` mounts outside `PhoneClassicPage`. Hoisting that constant in `<script setup>` (or setting the vars on `.driver-library.dl-phone`) avoids repeated allocation.

### 1. Critique of the Fix & Updated Source/Tests

- **Synchronous overlay reset ([`driverBrowsingState.ts:L574-L576`](http://lap:8000/winisd/openisd-t607/packages/ui/src/logic/driverBrowsingState.ts#L574-L576) & [`DriverBrowser.vue`](http://lap:8000/winisd/openisd-t607/packages/ui/src/ui/components/DriverBrowser.vue#L20-L37))**: Moving cleanup out of `DriverBrowser.vue` into `watch(() => presentationState.browseOpen, open => { if (!open) closeLibrary(); }, {flush: 'sync'})` in `driverBrowsingState.ts` resolves the stale-`projectInfoOpen` defect cleanly and keeps state lifecycle in `logic/`. Calling `closeLibrary()` when `open` is already `false` is idempotent and cannot loop.
- **Shell & hook wiring ([`MobileDriverTab-hooks.ts:L38`](http://lap:8000/winisd/openisd-t607/packages/ui/src/hooks/MobileDriverTab-hooks.ts#L38), [`OriginalShell-hooks.ts:L796`](http://lap:8000/winisd/openisd-t607/packages/ui/src/hooks/OriginalShell-hooks.ts#L796), [`OriginalShell.vue:L445-L447`](http://lap:8000/winisd/openisd-t607/packages/ui/src/ui/shells/original/OriginalShell.vue#L445-L447))**: Both shells delegate `showDriverInfo` straight to `driverBrowsing.showProjectDriverInfo` with no logic in the Vue templates.
- **Browser & unit test updates ([`driver-info.browser.spec.ts:L20-L53`](http://lap:8000/winisd/openisd-t607/packages/ui/test/ui/driver-info.browser.spec.ts#L20-L53), [`driverBrowsingState-info.test.ts:L7-L16`](http://lap:8000/winisd/openisd-t607/packages/ui/test/logic/driverBrowsingState-info.test.ts#L7-L16))**:
  - The browser spec now covers single-row alignment (`top` and `height` equality), non-overlap (`right <= left`), minimum button heights (`44px` phone / `20px` desktop), all three dismissal routes (`Close`, `h2 .x`, `Escape`), visible catalogue rows (`.wb-modal .dlist .ditem`) upon reopening `Select driver`, and opening `.de-modal` via `Edit`.
  - Minor non-blocking test note: in [`driverBrowsingState-info.test.ts:L12-L14`](http://lap:8000/winisd/openisd-t607/packages/ui/test/logic/driverBrowsingState-info.test.ts#L12-L14), `await nextTick()` before `expect(app.driverBrowsing.projectInfoOpen.value).toBe(false)` would also pass with a default async watcher; asserting immediately after `app.presentation.browseOpen = false` would directly lock in `{flush: 'sync'}`.

### 3. Benefit Assessment

- **Beneficial enhancement**: Adding `Info` between `Select driver` and `Edit` gives direct, read-only access to the existing driver summary (`EBP`, `Znom`, `Pe`, provenance metadata, links, and favourite toggle) for the embedded project driver—including custom or imported drivers absent from the bundled catalogue—without opening the full mutable editor or triggering a catalogue fetch.
