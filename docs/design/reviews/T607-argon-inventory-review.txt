### Bounded Step & Scope Assessment

The patch honestly implements a bounded DOM-inventory slice and records remaining scope in [FIELD_APPEARANCE_CATALOGUE.md:L406-L436](http://lap:8000/winisd/openisd-t607/docs/design/FIELD_APPEARANCE_CATALOGUE.md?html#L406-L436) without shrinking the overall objective:
- Replacing `measureCompactFields` with `measureFieldInventory` on the scoped suites is a genuine oracle upgrade (`measureCompactFields` in [compactFieldContract.ts:L16-L37](http://lap:8000/winisd/openisd-t607/packages/ui/test/fixtures/compactFieldContract.ts#L16-L37) still trusts rendered `data-field`/`data-access` and ignores non-`.ui-field` controls).
- Generating `CATALOGUE_INVENTORY` from `FIELD_APPEARANCES` via `CATALOGUE_EDITORS` ([fieldInventoryScenarios.ts:L72-L128](http://lap:8000/winisd/openisd-t607/packages/ui/test/fixtures/fieldInventoryScenarios.ts#L72-L128)) is valid schema-driven base-form checking (it maps abstract tuple metadata to concrete tags, `readOnly`, options, and parts rather than trusting rendered DOM attributes), distinct from independent reference/paint approval (which remains limited to 44 numeric forms in [field-renditions.browser.spec.ts:L52-L65](http://lap:8000/winisd/openisd-t607/packages/ui/test/ui/field-renditions.browser.spec.ts#L52-L65)).

However, the new oracle still contains concrete false-pass paths within its claimed scope.

### Concrete Findings

1. **[HIGH] Self-rooted `owner` selectors make row-part and inner-control checks vacuous on non-`.ui-field` controls**
   - **Where:** [fieldInventoryScenarios.ts:L36-L55](http://lap:8000/winisd/openisd-t607/packages/ui/test/fixtures/fieldInventoryScenarios.ts#L36-L55), [fieldInventory.ts:L47-L82](http://lap:8000/winisd/openisd-t607/packages/ui/test/fixtures/fieldInventory.ts#L47-L82), [fieldInventory.ts:L84-L92](http://lap:8000/winisd/openisd-t607/packages/ui/test/fixtures/fieldInventory.ts#L84-L92).
   - **Mechanism:** `choice()` sets `owner` to the `<select>` itself (`#mob-box-type,#og-box-type`, `#mob-n-drivers`, `#mob-wiring`), where `owner.matches(field.valueSelector)` is true (`L47`). `owner.querySelectorAll(...)` (`L68`, `L80`) therefore searches only inside `<select>`, while root reconciliation (`L84-L92`) omits `button`, `[role="button"]`, `.winisd-deviation-cue`, `.ui-field-dq-btn`, and `.ui-field-unit`. Any unexpected cue, unit, or sibling control inside those rows—or any stray `.catalogue-colour-readout` (present in `valueSelector` at [fieldInventoryScenarios.ts:L4](http://lap:8000/winisd/openisd-t607/packages/ui/test/fixtures/fieldInventoryScenarios.ts#L4) but omitted from `nativeControls` at [fieldInventory.ts:L84](http://lap:8000/winisd/openisd-t607/packages/ui/test/fixtures/fieldInventory.ts#L84))—passes silently.
   - **Minimal mutation:** `await surface.locator('#mob-box-type,#og-box-type').evaluate(el => { const cue = document.createElement('button'); cue.className = 'winisd-deviation-cue'; cue.textContent = '≠W'; el.after(cue); });` — passes `measureFieldInventory`.

2. **[HIGH] Field labels, `<select>` option text/disabled state, and `inert`/`aria-hidden`/`tabindex="-1"` suppression are unchecked**
   - **Where:** [fieldInventory.ts:L29](http://lap:8000/winisd/openisd-t607/packages/ui/test/fixtures/fieldInventory.ts#L29), [fieldInventory.ts:L56-L78](http://lap:8000/winisd/openisd-t607/packages/ui/test/fixtures/fieldInventory.ts#L56-L78), [fieldInventoryScenarios.ts:L26-L34](http://lap:8000/winisd/openisd-t607/packages/ui/test/fixtures/fieldInventoryScenarios.ts#L26-L34), [fieldInventoryScenarios.ts:L115-L124](http://lap:8000/winisd/openisd-t607/packages/ui/test/fixtures/fieldInventoryScenarios.ts#L115-L124).
   - **Mechanism:** No scenario declares `.ui-field-label`/`label` as a required part. `HTMLSelectElement` checking (`L62-L65`) inspects only `option.value`, ignoring `option.textContent` and `option.disabled`. `visible()` (`L29`) checks only CSS `visibility`/`opacity`; `disabled` (`L60`, `L75`) checks only `:disabled,[aria-disabled="true"]`. Marking a control/part `inert`, `aria-hidden="true"`, or `tabindex="-1"`, blanking option text, or deleting field labels passes. Furthermore, `opacity: 0` on a duplicate row/input makes `filter(visible)` (`L40`, `L84`, `L90`) ignore it while it still occupies layout height and tab order.
   - **Minimal mutation:** `await surface.locator('[data-field="box.fsc"] .ui-field-label').evaluate(el => el.remove());` or `await surface.locator('#mob-box-type option').first().evaluate(o => { o.textContent = ''; o.disabled = true; });` — passes `measureFieldInventory`.

3. **[MEDIUM] Overlapping spinner part selectors and weaker host cue contracts allow non-button cues and extra buttons**
   - **Where:** [fieldInventory.ts:L66-L82](http://lap:8000/winisd/openisd-t607/packages/ui/test/fixtures/fieldInventory.ts#L66-L82), [fieldInventoryScenarios.ts:L28-L33](http://lap:8000/winisd/openisd-t607/packages/ui/test/fixtures/fieldInventoryScenarios.ts#L28-L33), [fieldInventoryScenarios.ts:L119-L124](http://lap:8000/winisd/openisd-t607/packages/ui/test/fixtures/fieldInventoryScenarios.ts#L119-L124).
   - **Mechanism:** `declaredParts` unions matches across `spinners` (`.num-stepper-btn`) and `increase`/`decrease button` (`button[title=...]`) without asserting set equality (`spinners` == `{increase, decrease}`). In `numericOccurrence` (`L31-L32`), `model cue` omits `attributes: {type: 'button', 'aria-haspopup': 'dialog'}` (checked only in `catalogueOccurrence` at `L122`), and neither helper requires `DQ cue` to be an interactive `<button>`.
   - **Minimal mutation:** Replace `.winisd-deviation-cue` on Closed Box `Fsc` with `<span class="winisd-deviation-cue">≠W</span>`, or strip `title="Increase"` from one `.num-stepper-btn` and append a third `<button title="Increase">▲</button>` — both pass `measureFieldInventory`.

4. **[MEDIUM] Catalogue inventory lacks a fixed-96 cardinality assertion, conflates `BugToggle` with `Boolean`, and allows `.num-input-wrap` on readonly numbers**
   - **Where:** [field-catalogue.browser.spec.ts:L132-L141](http://lap:8000/winisd/openisd-t607/packages/ui/test/ui/field-catalogue.browser.spec.ts#L132-L141), [field-renditions.browser.spec.ts:L46-L50](http://lap:8000/winisd/openisd-t607/packages/ui/test/ui/field-renditions.browser.spec.ts#L46-L50), [fieldInventoryScenarios.ts:L68-L93](http://lap:8000/winisd/openisd-t607/packages/ui/test/fixtures/fieldInventoryScenarios.ts#L68-L93).
   - **Mechanism:** Both specs assert `FIELD_APPEARANCES.length` against itself rather than `96`. `CATALOGUE_EDITORS` maps `FieldEditor.BugToggle` and `FieldEditor.Boolean` to identical selectors/attributes (`L91-L92`), and `typedInput('text', true)` (`L75`, `L79`) matches `input[type="text"]` even if a readonly specimen remains inside `.num-input-wrap` with `data-numinput`.
   - **Minimal mutation:** Render `bug-toggle-*` specimens identically to `boolean-*`, or keep `data-numinput` on a readonly catalogue number input — `measureFieldInventory` passes.

5. **[LOW] Static template discovery omits `.mob-readonly`, `.catalogue-colour-readout`, and object-spread `v-bind`**
   - **Where:** [audit-field-control-sources.mjs:L12-L13](http://lap:8000/winisd/openisd-t607/scripts/audit-field-control-sources.mjs#L12-L13), [audit-field-control-sources.mjs:L34-L35](http://lap:8000/winisd/openisd-t607/scripts/audit-field-control-sources.mjs#L34-L35).
   - **Mechanism:** Runtime `measureFieldInventory` treats `.mob-readonly` and `.catalogue-colour-readout` as value controls, but static AST discovery only matches `input|select|textarea|meter`, ARIA roles, and literal `contenteditable="true"`, missing span-based readouts (`NumReadout.vue`) and unarged `v-bind="obj"` directives.
   - **Minimal regression:** Check that `entries` in `control-source-inventory.json` includes `NumReadout.vue`'s `.mob-readonly` declaration.
