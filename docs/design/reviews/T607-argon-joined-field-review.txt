### 4. Source Inspection: Actual Blockers vs Future Coverage Suggestions

#### Actual Blockers / Defects in the Selected Restoration

1. **Page-wide `.mob-classic:has(.ui-field-dev)` shrinks readonly and stepperless boxes on mixed pages ([joined-fields.css:L44-L45](http://lap:8000/winisd/openisd-t607/packages/ui/src/ui/joined-fields.css#L44-L45), [joined-fields.css:L71](http://lap:8000/winisd/openisd-t607/packages/ui/src/ui/joined-fields.css#L71))**:
   - Driver's `170px` box width on a `374px` viewport works only because `--joined-buttons: 90px` is unconditionally reserved in track 3 even on `.ui-field-readout` rows (`374 - 32 - 82 - 90 - 0 = 170px`), and Driver happens to have no `.ui-field-dev` on the page.
   - Because `.joined-fields.app-root-mobile .mob-classic:has(.ui-field-dev) .ui-field[data-field] { --joined-model: 24px; padding-right: 2px; }` is scoped to the whole `.mob-classic` container, any `.ui-field-readout` or `CountSelect` `<select>` on a mobile page that also contains a `.ui-field-dev` row is shrunk from `170px` to `160px` even though its `90px` spinner track (`grid-column: 3`) is completely empty.
2. **Stepperless rows with `≠W` on mobile get double left spacing (`4px` instead of `2px`) ([joined-fields.css:L53-L54](http://lap:8000/winisd/openisd-t607/packages/ui/src/ui/joined-fields.css#L53-L54))**:
   - Line 53 sets `.ui-field-dev { padding-left: 2px; }` and line 54 adds `:not(:has(.num-stepper)) .ui-field-dev { margin-left: 2px; }` on the same element when `grid-column: 3 / 5` is active (line 38), doubling the gap next to a `<select>` or readout box to `4px`.
3. **Outside-left `⚠` (`.ui-field-dq`) shares `grid-column: 1; grid-row: 1` with `<label>`, risking unmeasured label-to-`⚠` collision and vertical overflow on mobile ([joined-fields.css:L13-L14](http://lap:8000/winisd/openisd-t607/packages/ui/src/ui/joined-fields.css#L13-L14), [joined-fields.css:L35](http://lap:8000/winisd/openisd-t607/packages/ui/src/ui/joined-fields.css#L35), [joined-fields.css:L46-L49](http://lap:8000/winisd/openisd-t607/packages/ui/src/ui/joined-fields.css#L46-L49))**:
   - When `.ui-field-dq-btn` is present, `<label>` gets `padding-right: 22px` inside `--joined-label` (`82px` on mobile, leaving only `60px` for label text).
   - On desktop, `<label>` has `white-space: nowrap` (line 13) without `overflow: hidden`; inside a fixed-width track (`150px`), a label wider than `128px` overflows right directly under the `⚠` button.
   - On mobile, `<label>` has `white-space: normal` (line 49) without `overflow-wrap: break-word` inside a fixed `height: 40px` row (line 46, which only switches to `height: auto` when `.ui-field-note-open` is set on line 55). Any single word wider than `60px` overflows under `⚠`, and a label that wraps to 3 lines (`48px`) clips vertically while the note is closed.
   - **Test blind spot**: Neither [fieldVisualContract.ts:L33-L87](http://lap:8000/winisd/openisd-t607/packages/ui/test/fixtures/fieldVisualContract.ts#L33-L87) nor [joined-field.browser.spec.ts:L58-L71](http://lap:8000/winisd/openisd-t607/packages/ui/test/ui/joined-field.browser.spec.ts#L58-L71) measures `<label>` glyph bounds against `.ui-field-dq-btn` or `input` (`measureFieldContent` only reads `label.textContent` as a string identifier).

#### Non-Blocking Cleanup & Future Coverage Suggestions

- **Stale `.mob-ui-field` rule in [UnitToggle.vue:L83-L86](http://lap:8000/winisd/openisd-t607/packages/ui/src/ui/components/UnitToggle.vue#L83-L86)**: `.app-root-mobile .mob-ui-field.ui-field:has(input.de-input-mandatory) span.unit-label.unit-toggle` has higher specificity `(0,6,2)` than [joined-fields.css:L31](http://lap:8000/winisd/openisd-t607/packages/ui/src/ui/joined-fields.css#L31) `(0,6,0)` and forces `border-color: var(--mob-box-line)` without `border-right-width: 2px`. Safe today only because `UIFieldBody` does not emit `.mob-ui-field`, but should be removed so callers passing `class="mob-ui-field"` cannot break mandatory+DQ unit borders.
- **Unscoped `hasDq` in [NumInput.vue:L43](http://lap:8000/winisd/openisd-t607/packages/ui/src/ui/components/NumInput.vue#L43)**: `v-if="hasDq || (refusal !== '' && !hideMark)"` ignores `hideMark` when `hasDq` is true; changing to `v-if="!hideMark && (hasDq || refusal !== '')"` prevents an unplaced grid item if `dq` is ever passed to `NumInput` inside `UIFieldBody`.
- **Add `<label>` glyph overlap check to `measureFieldContent` ([fieldVisualContract.ts:L69](http://lap:8000/winisd/openisd-t607/packages/ui/test/fixtures/fieldVisualContract.ts#L69))**: Measure the `<label>` text `Range` and assert it does not intersect `.ui-field-dq-btn` or the value control.
