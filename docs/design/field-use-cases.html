Full field interaction design — words, equations and worked examples

Field interaction contract

Review or correct this description using the comment box below. This is the written reference for the gallery and app work, updated 27 October 2026. E, blinking inverse video, is the decided cursor. A–D are discarded alternatives. The rules below distinguish the intended interaction from the verification still outstanding; this document does not claim that every app page already conforms.

States · Digit selection · Step equations · Acceleration · Typing and validity · Touch and keyboard closure · Examples

1. What a field represents

A field has a declared value kind, editing capability, units, numeric bounds and, where applicable, an integer stride. Those intrinsic properties select its visual form. Its present value, provenance, requiredness, diagnostics, focus and temporary disabled state are separate facts. Calculated or defaulted values can still be editable; a stored value can be read-only.

A numeric control keeps separate concepts: the draft text you see, the last accepted model value, the native insertion caret, the highlighted spin digit, its place value, and whether a hold is running. A refused numerical draft may remain visible without changing the model. A caret position is not a value, a model-difference cue is not a value error, and an empty optional field is not an entered zero.

The reference number box is 108px wide and 34px tall in a 40px row. Each spinner target is 40×34px. Read-only numbers retain the same number-box size. Labels sit beside their controls; they are not stacked above them. Supported formatted values must fit their box, and labels should avoid wrapping where space permits. The handling of exceptionally long precision-bearing drafts still needs an explicit reviewed example; clipping must not be passed off as conformance.

2. Native caret and selected spin digit

The thin vertical text caret chooses where typing inserts or replaces text. The inverse marker shows which decimal place a spin will change. They must agree before the first step. Clicking or touching a digit chooses that digit. The minus sign and decimal mark are not digits.

  • A bare caret immediately after a digit chooses the digit to its left.
  • At the beginning of a number, or immediately after its decimal mark, a digit to the right can be chosen when there is no digit immediately to the left.
  • A caret after the final displayed digit chooses the final digit, including a trailing zero. For 123.4500|, the last zero is highlighted and the increment is 0.0001.
  • A one-digit selection chooses that selected digit. Moving the native caret updates the marker immediately; the marker must not remain on an earlier digit.
  • Only a field with no chosen or remembered caret uses the default tenths place. For a complete integer displayed without a decimal mark, the default is the units digit. No usable numeric text means there is nothing to spin.

On touch, the native caret is collapsed rather than forcing a one-character Android selection. The inverse marker supplies the visible digit choice. This keeps ordinary text editing available while avoiding a forced selection action for every digit tap.

Left/right arrow keys choose adjacent numeric digits, skipping the sign and decimal mark and stopping at the ends. They work while either spinner button has focus too. Up/down arrow keys increment/decrement the chosen place. Moving left/right stops the current repeating key/button action before selecting the new digit.

3. Decided inverse-video marker and focus

The chosen digit alternates between white text on blue and its ordinary presentation. The cycle is one second: the reference holds the inverse phase through approximately the first 55% and the ordinary phase for the rest. Reduced-motion preference uses a steady inverse marker. Ordinary text colour continues to describe provenance; the cursor must not turn a calculated value into an entered value.

The number and its own spinner buttons form one focus group. Moving focus from the number into its spinner keeps the digit choice and draft precision. Moving outside the group removes the marker and ends a hold. Selecting a digit must never blank, reset or numerically change the field. A new deliberate caret/digit choice replaces the remembered spin place.

4. Decimal-place stepping, in equations

Let x be the number in the displayed unit, q the direction (+1 for up, −1 for down), and p the chosen decimal-place exponent: units have p=0, tens p=1, tenths p=−1, and hundredths p=−2. A normal decimal step is:

Δ = 10^p
candidate = x + q × Δ
bounded = min(U, max(L, candidate))

L and U are the numeric limits converted into the displayed unit; absent upper bounds mean infinity. Sign/floor validation still applies separately before the model accepts the candidate.

For a digit at zero-based text index i, let d be the decimal-mark index, or the string length when there is no decimal mark. The sign is included in both text indices, so it cancels naturally:

p = d − i − 1   when i is before the decimal mark
p = d − i       when i is after the decimal mark

The implementation does the arithmetic on scaled decimal integers to avoid showing ordinary binary floating-point tails. If D is the larger of the existing fractional-digit count and −p:

integer = signed integer formed from the displayed digits, padded to D places
nextInteger = integer + q × 10^(p + D)
nextValue = nextInteger × 10^(−D)

The result is bounded, then rendered with D fractional digits. Trailing precision zeroes stay present during the spin. Zero is displayed without a minus sign. Holding does not change Δ; it changes how often this same step runs.

Integer-rule controls follow their declared stride instead of an arbitrary decimal place:

next = clamp(round(x) + q × stride, L, U)

For example, an even-order spinner with stride 2 moves 2 → 4 → 6. Discrete driver/vent/PR counts use their declared dropdown choices rather than inventing a free-form decimal editor. Counts and filter order are not interchangeable field kinds.

5. Carry, borrow and a number changing length

The remembered choice is a place value, not a fixed character offset. When a carry adds a leading digit, the marker moves to the same place in the new text. Thus 19.9 → 20.0 still marks tenths. When a borrow removes a leading digit, the marker can temporarily sit on the leading surviving digit while the original place remains remembered.

For a tens spin, 10.5 ↓ becomes 0.5, and ↑ returns to 10.5. The controller must not silently change that remembered tens step into a units or tenths step just because the number became shorter. The rule is:

p_next = p_remembered   while continuing the same spin choice
p_next = p_new_choice   after the person moves the caret or selects another digit

For example, deliberately moving the caret after the last digit of 0.5 chooses tenths and cancels the remembered tens place. An automatic carry/borrow is not that deliberate move.

6. Tap, keyboard hold and acceleration

A button press or up/down key press takes one step immediately. It waits 400ms before repeating. A held button and a held key use the same gradual acceleration. Releasing the button/key or cancelling its pointer stops repetition; no delayed extra step should run after release. Moving away from the field/browser must also end a running hold.

Let t be elapsed time in milliseconds since the hold began. Repetition starts at t=400. During repetition:

a(t) = clamp((t − 400) / 3000, 0, 1)
r(t) = 3 + 9 × a(t)                  steps per second
interval(t) = 1000 / r(t)            milliseconds

The rate begins at 3 steps/s and reaches 12 steps/s 3 seconds after repetition starts, at about 3.4 seconds from the original press. Intermediate rates are gradual. The selected decimal place stays fixed. Native operating-system key repeat must not add a second repeat stream on top of this one.

This caret-spinner design does not switch to multiplicative 10% jumps or round to two significant digits on release. Older proportional-spin helpers exist in the app's history, but those rules are not the selected caret-hold interaction.

7. Typing, pasting and accepted values

Normal typing remains available directly in the field. The numeric text grammar permits one optional leading minus, digits and at most one decimal mark. A comma is accepted as a decimal mark; spinning/pasting can normalise it to a dot. Letters, an extra decimal mark and corrupt numeric syntax are refused. Partial text such as an empty string, a lone minus or a lone decimal mark can exist during editing; that does not make it an accepted finite model value.

Pasting extracts the first numeric measurement from the pasted text: 12.5 Hz supplies 12.5, and 1,5 supplies 1.5. A paste containing no number, or an insertion that would leave invalid numeric syntax, is refused. This extraction does not mean exponent syntax or arbitrary expressions are valid in the editor.

A clearable optional field can be empty and clear its stored value to null. A required empty field shows the missing-value treatment. A field whose binding always requires a number refuses an empty draft and keeps its last accepted model value. These cases must not convert a blank to zero.

Validation has three distinct outcomes:

DraftResult
Allowed numeric syntax and valueAccept the model change; keep the chosen place and precision where applicable.
Numeric text outside its permitted value rulesKeep a visible refusal explanation; do not silently store the refused number. The draft and last accepted value can differ.
Inserted letters or malformed numeric syntaxRefuse the edit or restore accepted numeric text; never pass corrupt text to the model.

In the app, leaving a refused draft keeps that draft and its explanation; Escape restores the stored value. This gallery's generic refusal examples and Escape handling still require a complete parity audit, so that intended behaviour must not be mistaken for a blanket verified claim.

8. Lower limits, crossing zero and strict positivity

Spinning clamps to the field's numeric bounds. Typing is validated rather than silently forced into that interval. The sign/floor rule is an additional constraint:

floor = none:          no additional sign restriction
floor = non-negative:  value ≥ 0
floor = positive:      value > 0
accepted = finite(value) AND within numeric bounds AND satisfies floor

These validity checks apply after conversion into the model unit, not merely to the sign printed in the box: for example, a negative Celsius temperature need not be a negative absolute temperature.

Signed gain can cross zero in both directions. PR added mass can reach zero but cannot spin negative. Input power has a positive numeric minimum of 0.01W and stops there. Qms has a numeric minimum of zero but a strict-positive floor: a spun zero can be shown as a refused draft, while the last accepted Qms remains unchanged. The four live limit examples above expose those distinctions.

A narrower plausibility band is data-quality information, not automatically another hard clamp. A model-specific field may deliberately allow an out-of-range value to be entered so its diagnostic can explain the consequence. Such an exception comes from the field/context declaration; it is not permission for arbitrary controls to invent their own limits.

9. Units, display precision and model meaning

Units occupy their own place outside the number. A switchable unit has an underlined button/chip affordance and cycles through that field's declared units. A fixed unit is a plain label. A unitless field has no fake clickable blank unit. A read-only numeric value may still have switchable display units.

x_display = unitConversion(value_SI)
value_SI  = inverseUnitConversion(x_display)

Changing the display unit converts the displayed number and its bounds; it must preserve the physical model quantity. A spin changes one place in the currently displayed unit, then converts the candidate back to the model unit for validation. Field-declared precision and any precision carried by an entered quantity determine formatting; selecting a finer digit must not silently erase the precision already shown.

A unit change is a new display context. The marker, remembered place, text fit and limits must be checked against the new representation, rather than blindly reusing a character index from the old one. Full active-edit/unit-change and extreme-precision coverage remains part of the app conformance work.

10. Mobile typing, spinner focus and scroll pinning

Touch a digit to choose its spin position and immediately enter normal in-place editing with the phone keyboard. A normal edit does not require a long hold, an Edit button, a clearing action or a numeric-edit popup. Touching, focusing, or moving between the field and its own buttons never wipes its value. Any separate provenance inspection lock is a separate mode, not the default editing gesture.

Touching a spinner moves focus to that button so the software keyboard can close. The text box and target button must stay at the same visible-screen position under the finger. Content already below the field is insufficient by itself because the browser can adjust scrolling again while the keyboard closes.

The existing pin adds one screen of temporary space before the focus change, remembers the field's visible top position y₀, and corrects browser movement for 1500ms:

scrollCorrection = currentVisibleTop − y₀
scrollBy(scrollCorrection)           while the pin is holding

Visible position includes the visual viewport's pan offset, not merely layout-viewport coordinates. After the hold, extra space only shrinks as hidden space can be removed without moving the visible field:

removed = max(0, min(extraSpace, spaceHiddenBelowView))
extraSpace_next = extraSpace − removed

This is the ratchet: space must not grow again merely because the user scrolls. A new spinner press can establish a new pin. Mechanical resize/late-scroll regressions pass, but real-device keyboard behaviour remains something to verify on the phone; emulation is not physical-phone approval.

11. Other app gestures and their current gallery coverage

The app also spins a focused numeric box with the mouse wheel; an unfocused box leaves wheel scrolling to the page. Existing horizontal drag-to-spin starts from the pressed digit, preserves vertical page scrolling, and engages after an 8px horizontal dead zone. These gestures are not fully demonstrated by this static gallery adapter and must be included in the app/gallery parity audit.

For the existing app drag rule, z is horizontal displacement in CSS pixels; right is positive:

rate(z) = 0                                      when |z| < 8
rate(z) = sign(z) × min(60, 3 + 0.3 × (|z| − 8))  otherwise

The drag takes an immediate step when it engages, then accumulates whole steps at that signed rate. Returning into the dead zone stops accumulation. Clock ticks are sampled every 40ms in the app; an individual delayed tick is capped at 100ms in the shared drag rule so a stalled frame does not cause a large catch-up jump. This distance-based drag rate is separate from the time-based held-button acceleration above.

12. Access, provenance and the two independent cues

Read-only prevents changing the value; disabled means temporarily unavailable. Neither state should masquerade as an editable field. A read-only field has no value spinner. Native dropdowns represent declared finite choices, text fields remain text fields, and an intentional WinISD bug switch keeps its distinct warning appearance.

Entered values use green; calculated values use blue; defaulted values have their own blue treatment. The cursor must not change those meanings. Missing-required red, optional empty and disabled styling are separate states. A calculated value is not made read-only merely to obtain a convenient appearance or a narrower layout.

The ⚠ data-quality cue sits immediately outside the value on its left and explains a missing, questionable or inconsistent value or a derived symptom. The ≠W model-difference badge (the “!W” cue) sits outside on the right, hugging the last actual spinner or dropdown/control. It describes an applicable model difference from WinISD, independently of whether this particular number is valid. Either cue, both or neither can be present.

Both cues need an explanation that works on touch; a hover title alone is insufficient. The app's model cue opens its help dialog. The gallery currently uses a local demonstration explanation, so final popup parity remains to be completed. This explanation popup is different from the rejected popup for ordinary number editing.

14. What verification must prove

The real control must match its intrinsic field kind and the appropriate catalogue form. Tests must check actual native roles, access, allowed choices, visible paint, glyph fit, borders, control and label bounds, unit/cue separation, group alignment, sibling/diagram collisions and focus behaviour. Updating a bitmap or merely attaching a catalogue ID cannot make a wrong control conform.

Interaction checks must cover end-caret and selected digits, signed/comma/integer/trailing-zero text, carry and borrow, default selection, repeat timing/release, typed and pasted refusals, accepted-versus-draft values, zero/floor limits, unit changes, touch editing, focus transitions and keyboard-close pinning. Deliberate tiny style/geometry changes and wrong editor choices must be detected. Every actual field/page/state needs coverage; a passing handful of catalogue samples is insufficient.

Current boundary: the chosen cursor and recent end-caret behaviour have direct gallery/app regression evidence. The branch still has outstanding pane layout and broader state/renderer work. Mobile real-device coverage, extreme precision, full wheel/drag and popup parity, and all supported pages/contexts must not be described as complete on the strength of this written guide.
