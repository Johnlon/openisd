An open loudspeaker enclosure simulator that runs in any browser.

Speaker design belongs to everyone who builds.

1,603 drivers and 79 passive radiators are bundled with the app, ready to load.

WinISD

Many of us learned enclosure design on WinISD, by Linearteam. It stopped at version 0.7, runs on Windows only, has had no release since 2016, and its source was never opened, so nobody can carry it forward. OpenISD picks it up: the default circuit model reproduces WinISD's output, and it reads and writes WinISD .wdr driver files and .wpr projects.

Bigger tools exist and do more. WinISD is simple, familiar and trusted — so OpenISD takes it as the golden source, and is not afraid to improve on it where it is wrong.

Desktop and mobile versions

There are two versions of the app, one made for the desktop and one made for the phone. Each is laid out for its own screen, and the app picks the right one for yours. Like WinISD, both work offline once you have opened the app, so there is nothing you have to install.

If you would like it in your Start menu, dock or home screen like any other app, here is how to add it as an app.

Goals

  • Match WinISD, then go past it — the same numbers by default, so a WinISD user can trust the move.
  • No install, no licence, no platform — a browser is the whole requirement, on a desktop or a phone, and it works offline.
  • Checked, in public — every model is tested against the closed-form maths, in CI, on every commit.
  • Community-owned — MIT licensed, open repository, open backlog. It has to survive its author losing interest.
  • Open data — a shared driver library anyone can contribute a spec sheet to. It holds 1,603 drivers today.

What is distinctive

  • Alignment lives on the Box page, for every box type — WinISD offers the choice once, in the new-project wizard, and never again.
  • Switch one box from sealed to ported and back — same design, both ways, compared side by side.
  • No division-by-zero results and no crashes — an incomplete design says what is missing instead of producing a NaN or a blank window.
  • Modern cursor — hover, right-click to snap to a peak or trough, lock it, or type a frequency.
  • Data-quality marks — the app says when a driver's own stated parameters contradict each other, and which ones.
  • What-if? — change a driver's Thiele/Small parameters and see what each one does to the curves. It never saves: close it and your design is untouched.
  • Solvers that run in every direction — enter what you know, at either end, and it works out the rest.
  • Error messages that teach — what is wrong, which physics says so, and what to change.
  • Visible calculation provenance — trace any number back to the values and the formula it came from.

Where we differ from WinISD

Some numbers do not match WinISD's. Each one is written up — which tool is right, and why: WinISD gaps and bugs.
